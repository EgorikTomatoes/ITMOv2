## Context Pack для первого рабочего сценария

### Факты и правила

- Вход ожидается в теле запроса как JSON с ключом "diff" (TRAINING_PR.diff app/api.py:35–38)
- ReviewService формирует промпт: "Review this pull request and find problems:\n{diff}", ответа модели не структурирует (TRAINING_PR.diff app/review_service.py:19–22)
- Ответ API — словарь вида {"comment": строка} (TRAINING_PR.diff app/review_service.py:22)
- Проверки входа и обработка ошибок отсутствуют (TRAINING_PR.diff)
- Правила репозитория для сервиса (использовать при TO BE): SEC-1, API-1 (20 000 символов), REL-1 (timeout 10 c), OUT-1 (summary+risks+checks), SCOPE-1, QA-1, OBS-1 (CASE.md)

### Формат входа и результата

- Вход: JSON {"diff": string}
- Выход (AS IS): JSON {"comment": string}
- Выход (TO BE per OUT-1): {"summary": str, "risks": [{"file": str, "line": int, "evidence": str, "risk": str}], "checks": [str]}

### Ограничения и запрещённые действия

- SCOPE-1: сервис и AI только советуют; никаких approve/merge/изменений кода и GitHub-действий
- QA-1: включать риск только при подтверждении строкой diff или правилом репозитория
- OBS-1: не логировать содержимое diff и ответа модели; только request_id, длительность, статус

### Хороший пример

- Запрос: POST /api/reviews с телом {"diff": "diff --git a/..."}
- Ожидаемый ответ (TO BE): summary + до 3 рисков с file/line/evidence/risk, список checks; каждый риск подтверждён цитатой из diff или правилом

### Плохой пример

- Запрос без поля "diff" → KeyError и 500 (текущее поведение)
- Огромный дифф, приводящий к превышению лимитов LLM или долгому времени ответа; отсутствие 413 при >20 000 символов (нарушение API-1)

### Что пока неизвестно

- Целевая версия Python (использование dict[str, str] требует ≥3.9) — Допущение
- Доступность эндпоинта: публичный или внутренний? Требования к аутентификации — Открытый вопрос
- Политика ретраев LLM: есть ли повтор при timeout 10 c — Открытый вопрос
- Ограничения тарификации/квот — Открытый вопрос
