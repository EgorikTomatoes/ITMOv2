# Проблема и метрики

## Проблема

- Пользователь: внутренние разработчики и CI-боты, отправляющие PR-диффы на ревью через POST /api/reviews
- Ситуация: нужно безопасно и предсказуемо получить структурированное AI-ревью диффа
- Что происходит сейчас (AS IS): API принимает произвольный dict без схемы, извлекает payload["diff"] без проверки; ReviewService формирует свободный промпт и получает неструктурный текст; ошибки LLM приводят к 500; большой diff не ограничен
- Почему это мешает: 5xx из-за KeyError и необработанных исключений; риск утечки секретов в LLM; непредсказуемые затраты/таймауты на больших диффах; невозможность автоматизировать обработку результата из-за свободного текста
- Что не входит в задачу: аутентификация и авторизация; GitHub-интеграция и действия; изменение бизнес-процессов вне ревью; полная система мониторинга — только минимальные сигналы по OBS-1

## Метрики

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля 5xx для POST /api/reviews на невалидном теле | >0 при отсутствии поля "diff" (KeyError→500) | 0; вместо 5xx возвращается 422 Unprocessable Entity | При каждом релизе | Интеграционные тесты, логи API |
| HTTP 413 при diff > 20 000 символов (API-1) | Не реализовано | Всегда 413 для превышения лимита | При релизе и регрессии | Интеграционные тесты с большим телом |
| Время ответа p95 для валидных запросов | Базовое измерение фикстурой | ≤ 10 с с учётом REL-1; не хуже базовой p95 >10% | Недельный мониторинг | Интеграционные/нагрузочные замеры |
| Структурность ответа по OUT-1 | Свободный текст {"comment": str} | Структура: summary + risks[≤3] + checks; поля в risks: file, line, evidence, risk | При релизе | Контракт и unit-тесты парсинга |

## Почему изменение метрики подтвердит решение проблемы

- Снижение 5xx при неверном вводе подтверждает корректную валидацию и предсказуемые ошибки (422)
- Контроль размера и явный 413 подтверждают защиту от DoS/перерасхода
- Наличие структурированного ответа позволяет потребителям автоматизировать обработку и писать стабильные тесты
- Контроль p95 подтверждает отсутствие деградации производительности от валидации
