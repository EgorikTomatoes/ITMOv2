# Отчёт 1. Атаки на исходный сервис

Дата: 2026-10-30

Краткое резюме: сервис содержит множественные уязвимости — SQL-инъекции, IDOR, эскалация привилегий через заголовок X-Role, манипуляции ценой, чтение чужих файлов, XSS в отзывах, утечки через логи и небезопасные действия AI-ассистента. Ниже — PoC и рекомендации.

1) SQL-инъекции (/profile, /search, /assistant/context)
- Описание: f-string с подстановкой параметров без экранирования.
- Эксплуатация: GET /profile?id=1 OR 1=1
- Эффект: обход фильтрации, утечка всех профилей. Аналогично для order_id в assistant/context.
- Доказательство: evidence/before/sqli_profile.json, assistant_context_sqli.json
- Ремедиирование: использовать параметризованные запросы (SELECT ... WHERE id = ?), валидировать типы.

2) IDOR профилей и заказов
- Описание: доступ по произвольному id и глобальный список /orders.
- Эксплуатация: Alice читает /profile?id=2; GET /orders без авторизации.
- Эффект: утечка чужих данных.
- Доказательство: evidence/before/idor_profile_alice_reads_bob.json, orders_list_noauth.json
- Ремедиирование: требовать сессию, ограничивать владельцем, скрывать чужие записи.

3) Подмена роли через X-Role
- Описание: /admin/export доверяет заголовку X-Role от клиента.
- Эксплуатация: GET /admin/export с X-Role: staff
- Эффект: выгрузка всех профилей посторонним.
- Доказательство: evidence/before/role_spoof_export.json
- Ремедиирование: роль только из server-side сессии.

4) Манипуляция ценой
- Описание: POST /orders принимает произвольное поле price.
- Эксплуатация: price=1 при покупке лампы.
- Эффект: покупка по 1 RUB.
- Доказательство: evidence/before/price_tampering.json
- Ремедиирование: цену брать из каталога на сервере.

5) Доступ к чужим файлам
- Описание: /files читает произвольный путь в пределах песочницы.
- Эксплуатация: user=bob&path=receipt.txt; попытка добраться до private/operator-note.txt.
- Эффект: чтение чужих чеков, попытка служебной заметки (sandbox частично защищает, но логики доступа нет).
- Доказательство: evidence/before/files_cross_user.json, files_traversal_private.json
- Ремедиирование: ограничивать пользователя своей директорией, запрещать private для клиентов.

6) Утечка логов
- Описание: /debug/logs доступен всем и содержит тела и заголовки (включая токены и пароли при логине).
- Эксплуатация: GET /debug/logs
- Эффект: компрометация сессий.
- Доказательство: evidence/before/logs_leak.json
- Ремедиирование: доступ только staff; редактирование секретов.

7) XSS в отзывах
- Описание: текст отзывов рендерится как HTML без экранирования.
- Эксплуатация: публикация <script>alert(1)</script>
- Эффект: выполнение JS при просмотре.
- Доказательство: evidence/before/reviews_view_xss.json
- Ремедиирование: HTML-экранирование при выводе.

8) Prompt injection и небезопасная /assistant/execute
- Описание: сервер исполняет любое решение; клиент может экспортировать профили и удалять файлы.
- Эксплуатация: POST /assistant/execute с tool=export_profiles, delete_tree(".") или read_file чужого чека.
- Эффект: утечка данных и уничтожение файлов.
- Доказательство: evidence/before/assistant_exec_export_profiles.json, assistant_exec_delete_tree.json, assistant_exec_read_bob.json
- Ремедиирование: валидация решений по ролям и владению; запрет опасных действий клиентам.

См. полный список и сырцы запросов в practices/practice_06/evidence/before/index.json.
