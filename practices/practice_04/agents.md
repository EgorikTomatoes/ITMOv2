# Инструкции для AI-агентов

## Назначение проекта

Проект принимает русское предложение, переводит его на английский язык и
преобразует результат в корректное имя переменной для программного кода.
Перевод выполняется локальной моделью через Ollama.

## Область работы

- Работайте только внутри каталога `practices/practice_04`.
- Не изменяйте `presentation.pptx`.
- Не изменяйте файлы других практических работ.
- Не добавляйте внешние Python-зависимости без необходимости: текущая реализация
  использует стандартную библиотеку.

## Структура

- `variable_translator/cli.py` — интерфейс командной строки.
- `variable_translator/translator.py` — обращение к Ollama и форматирование имени.
- `Modelfile` — конфигурация специализированной модели Ollama.
- `tests/` — автоматические тесты.
- `README.md` — пользовательская документация.
- `Makefile` — основные команды проекта.

## Требования к поведению

- Вход: непустое предложение на русском языке.
- Выход: только валидное английское имя переменной.
- Стиль по умолчанию: `snake_case`.
- Поддерживаемые стили: `snake`, `camel`, `pascal`, `constant`.
- Имя не должно начинаться с цифры.
- Ошибки подключения к Ollama должны быть понятными пользователю.
- Ответ модели необходимо очищать и проверять перед выводом.

## Команды

Создание локальной модели:

```bash
make setup
```

Интерактивный запуск:

```bash
make run
```

Пример запуска с аргументом:

```bash
python3 -m variable_translator "количество активных пользователей"
```

Проверка тестов:

```bash
make test
```

## Правила внесения изменений

1. Сохраняйте совместимость с Python 3.9 и новее.
2. После изменений запускайте `make test`.
3. Для сетевых тестов подменяйте Ollama mock-объектом: тесты не должны зависеть
   от запущенного сервера или доступа к интернету.
4. При добавлении новой возможности обновляйте `README.md` и тесты.
5. Не выводите рассуждения модели, Markdown или пояснения вместо имени переменной.
