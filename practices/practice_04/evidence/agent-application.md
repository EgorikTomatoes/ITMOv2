# Применение окружения агентом

Дата проверки: 7 октября 2026 года. Агент: Codex.

## 1. Правила проекта

Перед изменениями агент прочитал `AGENTS.md`. В работе применены ограничения из
файла: изменения сделаны только внутри `practice_04`, `presentation.pptx` не
изменялся, новые зависимости не добавлялись, после правок назначена полная
проверка `make check`.

## 2. Skill

Агент загрузил `.agents/skills/tdd/SKILL.md` и оба связанных ресурса:
`tests.md` и `mocking.md`. Выбранный публичный seam — JSON-RPC метод
`tools/call`; тесты обращаются к нему через `dispatch`, не вызывают внутренние
функции нормализации и не требуют сети. Так как текущая правка исправляет
доказательства и документацию, а не поведение программы, новый искусственный
RED-тест не создавался. Проверенный результат существующего цикла находится в
`tdd-red.txt` и `tdd-green.txt`, повторная сфокусированная проверка публичного
seam — в `skill-run.txt`.

## 3. MCP tool

Агент вызвал `make mcp-demo`, который поднимает настоящий stdio MCP-сервер,
выполняет `initialize` и два запроса `tools/call`. Корректный кандидат
`number_of_active_users` вернул `valid: true`, ошибочный `42 пользователя`
вернул `isError: true`. Машинный транскрипт находится в `mcp-demo.txt`.

## 4. Автоматическая проверка

Агент запустил реальный hook командой:

```text
/Library/Developer/CommandLineTools/usr/bin/python3 -m pre_commit run \
  --files practices/practice_04/mcp_server/server.py \
  practices/practice_04/tests/test_mcp_server.py
```

Результат: `Practice 04 automatic checks — Passed`, exit code `0`. Hook вызвал
`scripts/pre-commit-check.sh`, а тот — `make check`. Полный итог сохранён в
`automatic-check.txt`.

## Зачем нужны подключения

- `AGENTS.md` автоматически сообщает агенту постоянные ограничения проекта.
- TDD-skill задаёт способ проверки поведения через публичный интерфейс.
- MCP даёт агенту узкую доменную проверку имени переменной.
- Hook автоматически возвращает агенту единый результат всех проверок до
  коммита.
