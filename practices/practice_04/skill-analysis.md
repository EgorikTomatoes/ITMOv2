# Разбор TDD-skill

Skill задаёт не абстрактный совет «писать тесты», а конкретный короткий цикл:
сначала наблюдаемое падение теста, затем минимальная реализация и только один
публичный срез за раз. Отдельные `tests.md` и `mocking.md` подгружаются лишь при
необходимости, поэтому основная инструкция остаётся компактной, а примеры и
правила моков не занимают контекст постоянно. В этой работе публичным seam стал
JSON-RPC метод `tools/call`, а Ollama не участвовала в MCP-тестах, то есть тесты
проверяли контракт tool без сети. Первоначальный RED → GREEN сохранён в
`evidence/tdd-red.txt` и `evidence/tdd-green.txt`: до реализации импорт
публичного MCP-модуля завершался ошибкой, после реализации проверки контракта
прошли. Повторное применение skill агентом, чтение связанных ресурсов и
проверка выбранного публичного seam зафиксированы отдельно в
`evidence/agent-application.md`.

Структура skill проверена штатным валидатором `skill-creator`:

```text
$ python3 .../skill-creator/scripts/quick_validate.py .agents/skills/tdd
Skill is valid!
```
