# Feature Specification: Ollama Precheck UI

**Feature Branch**: `001-ollama-precheck-ui`

**Created**: 2026-10-27 (revised 2026-10-28)

**Status**: Draft

**Input**: User description: "Фича: проверка и запуск Ollama перед переводом в VS Code extension Russian Variable Translator. Ты представляешь только UI-команду. Создай пользовательскую спецификацию интерфейса. Код не меняй. Желаемый сценарий: 1. Пользователь вызывает команду «Перевести текст в имя переменной». 2. До выбора стиля и ввода текста расширение проверяет Ollama. 3. Пока идёт проверка, пользователь видит состояние проверки. 4. Если Ollama работает, пользователь видит успешный статус, после чего продолжается существующий сценарий выбора стиля и перевода. 5. Если Ollama не работает, интерфейс предлагает действия: - «Запустить Ollama»; - «Повторить проверку»; - «Отмена». 6. Во время запуска показывается состояние «Ollama запускается». 7. После успешного запуска проверка повторяется, затем продолжается перевод. 8. При ошибке показывается понятное сообщение и возможность повторить попытку или отменить. 9. При отмене или ошибке документ не изменяется. 10. Существующие выбор стиля, ввод текста и вставка результата должны продолжить работать. Не проектируй внутренний алгоритм запуска процесса и API. Это зона команды логики. После создания спецификации остановись. Не создавай plan, tasks и код."

## User Scenarios & Testing (mandatory)

### UI State Matrix

- Loading (checking): «Проверка Ollama…» — отображается немедленно после запуска команды и перед любыми другими шагами; пользователь может отменить. (см. Contract § Operation Signatures → checkOllamaStatus)
- Running: «Ollama работает» — краткое подтверждение, затем автоматический переход к выбору стиля. (см. Contract § State Transition Table)
- Starting: «Ollama запускается…» — показывается после выбора «Запустить Ollama» при успешном старте процесса; далее ждём готовности. Отмена прерывает процесс без изменений документа. (см. Contract § State Transition Table)
- Stopped: «Ollama не запущена» — показывается как результат проверки. Доступность действия «Запустить Ollama» определяется canStartLocal=true. (см. Contract § Data Types → OllamaStatus)
- Error: текст зависит от errorCode (см. раздел «Ошибки и тексты» ниже). Доступность «Запустить Ollama» также зависит от canStartLocal. (см. Contract § Error Table)

### User Story 1 - Предпроверка Ollama перед переводом (Priority: P1)

Как пользователь VS Code, я запускаю команду «Перевести текст в имя переменной» и хочу, чтобы расширение сначала проверило доступность Ollama и показало понятный статус, чтобы я понимал, что произойдёт дальше, и затем продолжило текущий сценарий перевода без лишних действий с моей стороны, если всё в порядке.

**Why this priority**: Это основной путь для всех пользователей функции перевода; без него пользователь не понимает состояние системы и не может быстро перейти к переводу.

**Independent Test**: При state=running от checkOllamaStatus UI показывает «Ollama работает» и автоматически открывает выбор стиля без дополнительных кликов. (см. Contract § Compliance 1–2)

**Acceptance Scenarios**:

1. Given пользователь запускает команду, When UI вызывает checkOllamaStatus, Then показывается «Проверка Ollama…» до получения результата (Cancel прерывает операцию). (Contract § Operation Signatures)
2. Given checkOllamaStatus вернул state=running, When UI снимает индикатор, Then показывается «Ollama работает» и автоматически открывается выбор стиля; далее — ввод текста и вставка результата без изменений сценария. (Contract § State Transition Table; § Compliance 1–2)

---

### User Story 2 - Ведение пользователя при недоступной Ollama (Priority: P2)

Как пользователь, если Ollama недоступна, я хочу увидеть варианты «Запустить Ollama» (только если canStartLocal=true), «Повторить проверку», «Отмена», чтобы я мог быстро исправить ситуацию или выйти без изменений в документе. (Contract § Data Types → OllamaStatus.canStartLocal)

**Why this priority**: Обеспечивает управляемый выход из нештатной ситуации и минимизирует фрустрацию.

**Independent Test**:
- При state=stopped и canStartLocal=true UI предлагает «Запустить», «Повторить», «Отмена». (Contract § State Transition Table)
- При state=stopped и canStartLocal=false кнопка «Запустить» отсутствует; доступны «Повторить», «Отмена». (Contract § Error Table/Responsibilities)

**Acceptance Scenarios**:

1. Given checkOllamaStatus вернул state=stopped, When UI формирует экран, Then показывается «Ollama не запущена» и действия: «Повторить», «Отмена», а «Запустить» показывается только если canStartLocal=true. (Contract § Data Types → canStartLocal)
2. Given canStartLocal=true, When пользователь выбирает «Запустить Ollama», Then UI показывает «Ollama запускается…», далее UI ожидает готовность и при подтверждении running автоматически продолжает сценарий перевода; при ошибке — показывает текст ошибки и «Повторить»/«Отмена». (Contract § State Transition Table)
3. Given отображены действия, When пользователь выбирает «Повторить проверку», Then UI снова вызывает checkOllamaStatus и показывает «Проверка Ollama…» на время ожидания. (Contract § Operation Signatures)
4. Given любой экран ожидания/ошибки, When пользователь выбирает «Отмена», Then UI отменяет текущую операцию; логика возвращает user-cancelled; документ не изменяется. (Contract § State Transition Table row "any → error(user-cancelled)")

---

### User Story 3 - Отмена на любом этапе (Priority: P3)

Как пользователь, я хочу иметь возможность отменить процесс на любом этапе (во время проверки, после ошибки, при выборе действий, при выборе стиля, при вводе текста), чтобы документ не менялся и я мог вернуться к работе.

**Why this priority**: Гарантирует безопасность и предсказуемость UX.

**Independent Test**: На каждом этапе выбрать «Отмена» или закрыть диалог и убедиться, что документ остаётся неизменным.

**Acceptance Scenarios**:

1. Given идёт проверка, When пользователь отменяет действие (закрывает индикатор/диалог), Then процесс прерывается без изменений в документе.
2. Given показаны варианты после ошибки, When пользователь выбирает «Отмена», Then процесс завершается, документ не меняется.
3. Given открыт выбор стиля или ввод текста, When пользователь отменяет, Then документ не меняется (сохраняется текущее поведение).

---

### Edge Cases

- Очень медленная проверка: UI непрерывно показывает состояние «Проверка Ollama…» до завершения проверки; пользователь может отменить ожидание.
- Повторные ошибки запуска: при нескольких подряд неудачных попытках запуска показывается понятное сообщение и остаются доступными «Повторить проверку» и «Отмена». (Contract § Error Table)
- Частичный успех (Ollama запустилась, но проверка всё ещё не проходит): UI трактует это как ошибку проверки и снова предлагает «Повторить проверку»/«Отмена»/«Запустить Ollama» (если уместно), без изменений документа.
- Изменённый адрес Ollama в настройках пользователя: текст ошибки должен использовать нейтральные формулировки без технических деталей, предлагая действия, а не утекающие детали реализации.
- Пользователь закрывает любые всплывающие окна/индикаторы: трактуется как отмена, изменений в документе нет.

## Requirements (mandatory)

### Functional Requirements

- FR-001: При запуске команды «Перевести текст в имя переменной» сначала отображается состояние проверки Ollama до любого другого UI (до выбора стиля и ввода текста).
- FR-002: Текст состояния проверки: «Проверка Ollama…» (индикатор выполнения/загрузки).
- FR-003: Если checkOllamaStatus возвращает state=running, UI показывает «Ollama работает», после чего автоматически открывается существующий выбор стиля. Дальше сценарий идентичен текущему: выбор стиля → ввод текста → вставка результата в позицию курсора. (Contract § Compliance 1–2)
- FR-004: Если state=stopped|error, UI показывает сообщение и действия: «Повторить проверку», «Отмена»; «Запустить Ollama» показывается только если canStartLocal=true. (Contract § Data Types → OllamaStatus.canStartLocal; § Responsibilities)
- FR-005: При выборе «Запустить Ollama» UI отображает «Ollama запускается…», затем ожидает готовности до итогового состояния. На running — продолжение перевода; на error — текст ошибки и действия «Повторить проверку»/«Отмена». (Contract § State Transition Table: stopped→starting→running|error)
- FR-006: При выборе «Повторить проверку» UI вызывает checkOllamaStatus и показывает «Проверка Ollama…» до получения результата; дальнейшие действия зависят от результата. (Contract § Operation Signatures)
- FR-007: При выборе «Отмена» процесс полностью останавливается; документ не изменяется; никакие диалоги выбора стиля/ввода текста не открываются.
- FR-008: На всех этапах отмена (закрытие окна/диалога/индикатора) эквивалентна действию «Отмена» и не приводит к изменениям документа; логика возвращает errorCode=user-cancelled. (Contract § State Transition Table; § Error Table)
- FR-009: Тексты UI (точные строки):
  - Состояние проверки: «Проверка Ollama…»
  - Успешное состояние (running): «Ollama работает» (краткое подтверждение перед переходом к следующему шагу)
  - Состояние запуска (starting): «Ollama запускается…»
  - Состояние остановлено (stopped): «Ollama не запущена»
  - Состояние ошибка (error) — отображение по errorCode: см. «Ошибки и тексты» ниже
  - Варианты действий при остановке/ошибке: всегда «Повторить проверку», «Отмена»; «Запустить Ollama» — только при canStartLocal=true
- FR-010: Существующий функционал выбора стиля, ввода текста и вставки результата работает без изменений по содержанию и порядку после успешной проверки (state=running). (Contract § Compliance 2)
- FR-011: Ни при каких ошибках или отменах документ не изменяется (в т.ч. errorCode: health-timeout, http-error, network-error, user-cancelled, unsupported-platform, ollama-not-found, port-busy, start-timeout, start-failed). (Contract § Error Table; § Compliance 6)

- FR-012: UI не должен предлагать «Запустить Ollama», если canStartLocal=false. (Contract § Data Types → OllamaStatus.canStartLocal)

### Ошибки и тексты (классификация UI)

UI использует локализованные тексты, сопоставляя errorCode из контракта со следующими сообщениями (примерные формулировки для приёмки; UI может уточнять): (см. Contract § Error Table)
- health-timeout → «Проверка Ollama заняла слишком долго»
- http-error → «Ollama недоступна»
- network-error → «Не удалось подключиться к Ollama»
- start-timeout → «Ollama не запустилась вовремя»
- start-failed → «Не удалось запустить Ollama»
- port-busy → «Порт Ollama занят»
- ollama-not-found → «Команда “ollama” не найдена»
- unsupported-platform → «Автозапуск Ollama недоступен на этой платформе»
- user-cancelled → ошибка не показывается; UI завершает сценарий без изменений документа

### Key Entities

Не применимо (только UI-поведение команды).

## Success Criteria (mandatory)

### Measurable Outcomes

- SC-001: В 100% запусков команды до выбора стиля UI показывает «Проверка Ollama…» на время вызова checkOllamaStatus. (Contract § Compliance 1)
- SC-002: В 100% случаев, когда checkOllamaStatus вернул state=running, UI автоматически открывает выбор стиля без дополнительных кликов. (Contract § Compliance 2)
- SC-003: В 100% случаев state=stopped UI предлагает «Повторить», «Отмена», и «Запустить» только при canStartLocal=true. (Contract § Responsibilities)
- SC-004: В 100% случаев выбора «Запустить Ollama» UI показывает «Ollama запускается…» до итогового состояния и на running продолжает перевод без дополнительных кликов. (Contract § State Transition Table)
- SC-005: Для каждого из errorCode из таблицы контракта UI показывает соответствующее сообщение (см. раздел «Ошибки и тексты»); «user-cancelled» не показывает ошибку. Покрытие: все коды из таблицы. (Contract § Error Table)
- SC-006: В 100% случаев ошибок или отмен документ остаётся неизменным. (Contract § Compliance 6)

## Assumptions

- Пользователь имеет установленную локальную Ollama и соответствующую модель; механизм запуска и проверок реализует команда логики (вне данной спецификации UI).
- Временная длительность проверки/запуска не нормируется данной спецификацией; UI обязан отображать понятное состояние на всём протяжении ожидания и позволять отмену.
- Сообщения об ошибках оставляют технические детали за пределами UI и формулируются пользовательски (например, «Ollama недоступна»), предлагая действия без раскрытия внутренней реализации.
- Доступные локализации — русская; иные языки — вне объёма данной задачи.

## Out of Scope

- Внутренние алгоритмы и API проверки доступности и запуска Ollama (разрабатываются командой логики).
- Изменение текущей логики перевода, форматирования и вставки результата (поведение после успешной проверки остаётся прежним).
- Любые изменения настроек расширения, конфигурационных экранов и хранилищ настроек.
- Телеметрия, логирование, аналитика использования UI.
- Дополнительные локализации интерфейса (кроме русской) и настройка пользовательских текстов.
- Автоматическое изменение пользователя настроек либо автозапуск внешних процессов вне явного выбора «Запустить Ollama» пользователем.
