# Feature Specification: Ollama Precheck UI

**Feature Branch**: `001-ollama-precheck-ui`

**Created**: 2026-10-27

**Status**: Draft

**Input**: User description: "Фича: проверка и запуск Ollama перед переводом в VS Code extension Russian Variable Translator. Ты представляешь только UI-команду. Создай пользовательскую спецификацию интерфейса. Код не меняй. Желаемый сценарий: 1. Пользователь вызывает команду «Перевести текст в имя переменной». 2. До выбора стиля и ввода текста расширение проверяет Ollama. 3. Пока идёт проверка, пользователь видит состояние проверки. 4. Если Ollama работает, пользователь видит успешный статус, после чего продолжается существующий сценарий выбора стиля и перевода. 5. Если Ollama не работает, интерфейс предлагает действия: - «Запустить Ollama»; - «Повторить проверку»; - «Отмена». 6. Во время запуска показывается состояние «Ollama запускается». 7. После успешного запуска проверка повторяется, затем продолжается перевод. 8. При ошибке показывается понятное сообщение и возможность повторить попытку или отменить. 9. При отмене или ошибке документ не изменяется. 10. Существующие выбор стиля, ввод текста и вставка результата должны продолжить работать. Не проектируй внутренний алгоритм запуска процесса и API. Это зона команды логики. После создания спецификации остановись. Не создавай plan, tasks и код."

## User Scenarios & Testing (mandatory)

### UI State Matrix

- Loading (checking): «Проверка Ollama…» — отображается немедленно после запуска команды и перед любыми другими шагами; пользователь может отменить.
- Running: «Ollama работает» — краткое подтверждение, затем автоматический переход к выбору стиля.
- Starting: «Ollama запускается…» — показывается после выбора «Запустить Ollama» до завершения попытки запуска; отмена прерывает процесс без изменений документа.
- Stopped: «Ollama не запущена» — показывается как результат проверки, предлагаются действия: «Запустить Ollama», «Повторить проверку», «Отмена».
- Error: «Не удалось подключиться к Ollama» — показывается как результат проверки при ошибке соединения/другой сбое; предлагаются действия: «Запустить Ollama», «Повторить проверку», «Отмена».

### User Story 1 - Предпроверка Ollama перед переводом (Priority: P1)

Как пользователь VS Code, я запускаю команду «Перевести текст в имя переменной» и хочу, чтобы расширение сначала проверило доступность Ollama и показало понятный статус, чтобы я понимал, что произойдёт дальше, и затем продолжило текущий сценарий перевода без лишних действий с моей стороны, если всё в порядке.

**Why this priority**: Это основной путь для всех пользователей функции перевода; без него пользователь не понимает состояние системы и не может быстро перейти к переводу.

**Independent Test**: Запустить команду при работающей Ollama. Убедиться, что появляется индикатор проверки, затем короткий успешный статус, после чего отображается выбор стиля и перевод проходит штатно.

**Acceptance Scenarios**:

1. Given пользователь запускает команду, When начинается проверка Ollama, Then пользователь видит состояние «Проверка Ollama…» и другие элементы UI ещё не показаны.
2. Given Ollama доступна, When проверка завершается, Then пользователь видит «Ollama работает» (краткий успешный статус), после чего открывается выбор стиля и процесс перевода продолжается как сейчас.

---

### User Story 2 - Ведение пользователя при недоступной Ollama (Priority: P2)

Как пользователь, если Ollama недоступна, я хочу увидеть варианты «Запустить Ollama», «Повторить проверку», «Отмена», чтобы я мог быстро исправить ситуацию или выйти без изменений в документе.

**Why this priority**: Обеспечивает управляемый выход из нештатной ситуации и минимизирует фрустрацию.

**Independent Test**: Остановить Ollama, запустить команду, убедиться в отображении вариантов действий; выбрать каждый вариант по очереди и проверить ожидаемое поведение.

**Acceptance Scenarios**:

1. Given Ollama недоступна, When завершилась проверка, Then отображается соответствующее сообщение (либо «Ollama не запущена», либо «Не удалось подключиться к Ollama») с вариантами «Запустить Ollama», «Повторить проверку», «Отмена».
2. Given видны варианты, When пользователь выбирает «Запустить Ollama», Then UI показывает состояние «Ollama запускается», затем выполняется повторная проверка автоматически; при успехе — продолжается перевод (выбор стиля и далее), при ошибке — показывается понятное сообщение с возможностью «Повторить проверку» или «Отмена».
3. Given видны варианты, When пользователь выбирает «Повторить проверку», Then запускается повторная проверка и UI снова показывает состояние проверки, после чего сценарий продолжается в зависимости от результата.
4. Given видны варианты, When пользователь выбирает «Отмена», Then сценарий завершается, никаких изменений в документ не вносится.

---

### User Story 3 - Отмена на любом этапе (Priority: P3)

Как пользователь, я хочу иметь возможность отменить процесс на любом этапе (во время проверки, после ошибки, при выборе действий, при выборе стиля, при вводе текста), чтобы документ не менялся и я мог вернуться к работе.

**Why this priority**: Гарантирует безопасность и предсказуемость UX.

**Independent Test**: На каждом этапе выбрать «Отмена» или закрыть диалог и убедиться, что документ остаётся неизменным.

**Acceptance Scenarios**:

1. Given идёт проверка, When пользователь отменяет действие (закрывает индикатор/диалог), Then процесс прерывается без изменений в документе.
2. Given показаны варианты после ошибки, When пользователь выбирает «Отмена», Then процесс завершается, документ не меняется.
3. Given открыт выбор стиля или ввод текста, When пользователь отменяет, Then документ не меняется (сохраняется текущее поведение).

---

### Edge Cases

- Очень медленная проверка: UI непрерывно показывает состояние «Проверка Ollama…» до завершения проверки; пользователь может отменить ожидание.
- Повторные ошибки запуска: при нескольких подряд неудачных попытках запуска показывается понятное сообщение и остаются доступными «Повторить проверку» и «Отмена».
- Частичный успех (Ollama запустилась, но проверка всё ещё не проходит): UI трактует это как ошибку проверки и снова предлагает «Повторить проверку»/«Отмена»/«Запустить Ollama» (если уместно), без изменений документа.
- Изменённый адрес Ollama в настройках пользователя: текст ошибки должен использовать нейтральные формулировки без технических деталей, предлагая действия, а не утекающие детали реализации.
- Пользователь закрывает любые всплывающие окна/индикаторы: трактуется как отмена, изменений в документе нет.

## Requirements (mandatory)

### Functional Requirements

- FR-001: При запуске команды «Перевести текст в имя переменной» сначала отображается состояние проверки Ollama до любого другого UI (до выбора стиля и ввода текста).
- FR-002: Текст состояния проверки: «Проверка Ollama…» (индикатор выполнения/загрузки).
- FR-003: Если проверка успешна, пользователь видит краткое подтверждение «Ollama работает», после чего автоматически открывается существующий выбор стиля. Дальше сценарий идентичен текущему: выбор стиля → ввод текста → вставка результата в позицию курсора.
- FR-004: Если проверка неуспешна, UI показывает сообщение об ошибке и три действия: «Запустить Ollama», «Повторить проверку», «Отмена».
- FR-005: При выборе «Запустить Ollama» отображается состояние «Ollama запускается», затем выполняется повторная проверка автоматически. При успешной проверке продолжается стандартный сценарий перевода. При ошибке — показывается понятное сообщение и снова доступны «Повторить проверку» и «Отмена».
- FR-006: При выборе «Повторить проверку» запускается проверка с теми же визуальными состояниями, что и изначально («Проверка Ollama…» → успех/ошибка), без побочных эффектов.
- FR-007: При выборе «Отмена» процесс полностью останавливается; документ не изменяется; никакие диалоги выбора стиля/ввода текста не открываются.
- FR-008: На всех этапах отмена (закрытие окна/диалога/индикатора) эквивалентна действию «Отмена» и не приводит к изменениям документа.
- FR-009: Тексты UI (точные строки):
  - Состояние проверки: «Проверка Ollama…»
  - Успешное состояние (running): «Ollama работает» (может отображаться кратко или как подтверждающий текст перед переходом к следующему шагу)
  - Состояние запуска (starting): «Ollama запускается…»
  - Состояние остановлено (stopped): «Ollama не запущена»
  - Состояние ошибка (error): «Не удалось подключиться к Ollama»
  - Варианты действий при остановке/ошибке: «Запустить Ollama», «Повторить проверку», «Отмена»
- FR-010: Существующий функционал выбора стиля, ввода текста и вставки результата работает без изменений по содержанию и порядку после успешной проверки.
- FR-011: Ни при каких ошибках или отменах документ не изменяется.

### Key Entities

Не применимо (только UI-поведение команды).

## Success Criteria (mandatory)

### Measurable Outcomes

- SC-001: Во всех запусках команды до выбора стиля пользователь видит состояние «Проверка Ollama…» (100% случаев).
- SC-002: При доступной Ollama переход от начала проверки до появления выбора стиля происходит без дополнительных кликов со стороны пользователя (100% случаев).
- SC-003: При недоступной Ollama пользователь видит три действия («Запустить Ollama», «Повторить проверку», «Отмена») и может завершить сценарий без изменений документа (100% случаев отмены).
- SC-004: После выбора «Запустить Ollama» при успешном запуске проверка повторяется автоматически и сценарий переходит к переводу без дополнительных действий (100% случаев успешного запуска).
- SC-005: Нулевая доля нежелательных изменений в документе при любой ошибке/отмене (0 инцидентов в тестовой матрице).

## Assumptions

- Пользователь имеет установленную локальную Ollama и соответствующую модель; механизм запуска и проверок реализует команда логики (вне данной спецификации UI).
- Временная длительность проверки/запуска не нормируется данной спецификацией; UI обязан отображать понятное состояние на всём протяжении ожидания и позволять отмену.
- Сообщения об ошибках оставляют технические детали за пределами UI и формулируются пользовательски (например, «Ollama недоступна»), предлагая действия без раскрытия внутренней реализации.
- Доступные локализации — русская; иные языки — вне объёма данной задачи.

## Out of Scope

- Внутренние алгоритмы и API проверки доступности и запуска Ollama (разрабатываются командой логики).
- Изменение текущей логики перевода, форматирования и вставки результата (поведение после успешной проверки остаётся прежним).
- Любые изменения настроек расширения, конфигурационных экранов и хранилищ настроек.
- Телеметрия, логирование, аналитика использования UI.
- Дополнительные локализации интерфейса (кроме русской) и настройка пользовательских текстов.
- Автоматическое изменение пользователя настроек либо автозапуск внешних процессов вне явного выбора «Запустить Ollama» пользователем.
