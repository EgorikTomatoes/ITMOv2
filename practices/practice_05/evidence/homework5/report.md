# ДЗ 5: Проверка и запуск Ollama перед переводом (VS Code Russian Variable Translator)

## 1. Название и цель фичи

- Название: Ollama Precheck UI & Logic
- Цель: Перед началом перевода проверять доступность локальной Ollama, показывать пользователю понятные статусы и действия (повтор/запуск/отмена), при необходимости запускать локальную Ollama и ждать готовности с дедлайном, а при доступности — продолжать текущий сценарий выбора стиля и перевода без лишних шагов.

## 2. Почему выбран Spec Kit

- Spec Kit даёт быстрый цикл спецификация → задачи → реализация → согласование между командами с минимальными накладными расходами, что удобно для учебного задания и brownfield-проекта.
- Простая файловая организация и команды упрощают работу в существующем репозитории без тяжёлых интеграций.

## 3. Краткое сравнение Spec Kit и OpenSpec

- Организация артефактов:
  - Spec Kit: specs/<feature> (spec.md, tasks.md, план/артефакты), evidence/ — единый, лёгкий стек.
  - OpenSpec: более формальная структура, изменяемые дельта/основные спеки, архивы изменений.
- Команды workflow:
  - Spec Kit: /speckit.specify → /speckit.tasks → /speckit.implement → /speckit.converge (эквивалентно) — короткий цикл.
  - OpenSpec: расширенный набор (propose/apply/update/sync/archive) — больше ритуала.
- Уточнение требований:
  - Spec Kit: встроенная /clarify с вопросами и инкрементальным внесением правок.
  - OpenSpec: артефакты и дельта-спеки, больше формальности.
- Планирование:
  - Spec Kit: tasks.md с фазами, приоритетами и явным перечислением файлов.
  - OpenSpec: детальная декомпозиция и связь с общими спецификациями.
- Реализация:
  - Spec Kit: привязка к tasks.md, TDD-first, DI акценты; удобен для локальной разработки.
  - OpenSpec: чаще нацелен на более масштабные команды и среду.
- Проверка согласованности:
  - Spec Kit: /converge добавляет недостающие задачи по факту кода.
  - OpenSpec: строгие процедуры синхронизации и архивирования.
- Удобство для brownfield:
  - Spec Kit: лучше подходит для постепенного вплетения фичи в существующий код, без перелопачивания процессов.

## 4. Роли двух команд

- UI-команда: проектирует и реализует пользовательский поток в VS Code — статусы «Проверка…», «Запускается…», действия «Запустить/Повторить/Отмена», продолжение стандартного перевода при running.
- Команда логики: предоставляет операции checkOllamaStatus, startOllama, waitUntilOllamaReady; возвращает состояния, errorCode, canStartLocal, обеспечивает таймауты/DI и безопасность запуска.

## 8. Противоречия и принятые человеком решения

- Противоречия:
  - starting как промежуточное состояние → в UI показывается только как прогресс, не как финальный результат.
  - Предлагать «Запустить» только при canStartLocal=true.
  - Возврат детальных errorCode логикой → UI отображает безопасные тексты.
  - Отмена и тайм-ауты должны прерывать без изменений документа.
- Решения:
  - Принят контракт с canStartLocal, ErrorCode и с on-progress в UI.
  - UI показывает действия согласно canStartLocal и тексты по errorCode.
  - running ведёт сразу к стандартному переводу.

## 11. Сценарий короткого демо

1) Запущена Ollama: вызвать команду → уведомление «Ollama работает» (коротко) → диалог выбора стиля → ввод текста → вставка результата.
2) Ollama остановлена (например, поменять ollamaUrl на http://localhost:9): вызвать команду → «Проверка Ollama…» → диалог с «Запустить» (если macOS + localhost), «Повторить», «Отмена». Выбрать «Запустить» → «Ollama запускается…» → при успехе продолжить перевод; при ошибке показать текст по errorCode.

## 12. Рефлексия: чему научились

- Разделение обязанностей UI и логики по контракту.

- DI и тестирование без реальной Ollama: мок fetch/процесс/таймер.
- Итеративное согласование через Spec Kit: спецификации → контракт → converge-задачи → минимальные правки кода.
