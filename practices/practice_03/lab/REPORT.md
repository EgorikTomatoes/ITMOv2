# Отчёт по практике 3: локальный помощник по проекту

## Окружение

- Компьютер: MacBook Air, Apple M3 (8 ядер), 16 ГБ памяти, arm64.
- ОС: macOS 26.5.2.
- Ollama: 0.35.1.
- OpenCode: 1.18.34.
- Python для тестов: 3.14.3.

## Модель

- Модель OpenCode: `ollama/itmo-chat`.
- ID модели Ollama: `b0d8da5513db`.
- Базовая модель: `qwen3.5:4b`, ID `d8b0f5e9760c`.
- Размер: 4,2 млрд параметров, 3,3 ГБ.
- Квантизация: `Q4_K_M`.
- Контекст модели: 8192 токена; максимальный вывод OpenCode: 1024 токена.
- Параметры: `temperature 0`, `seed 42`.

Модель на 4,2 млрд параметров выбрана как компромисс между качеством ответов и работой на ноутбуке с 16 ГБ памяти. Контекст 4096 оказался слишком мал для истории вызовов инструментов OpenCode: в первом запуске агент дошёл до автоматического продолжения вместо завершения ответа. После увеличения контекста до 8192 и ограничения вывода до 1024 сессии стали завершаться без переполнения контекста.

## Воспроизведение

Команды выполняются из каталога `lab/`:

```bash
make model  # собрать itmo-chat из Modelfile
make test   # выполнить три unit-теста
make demo   # запустить пять независимых сессий OpenCode
```

`make demo` использует агента `local-guide` из `demo/opencode.json`. Агент может только читать файлы и выполнять поиск; остальные разрешения запрещены. Каждый вопрос запускается новой командой `opencode run`, поэтому контекст предыдущего ответа не переносится. Полные события OpenCode, включая вопросы, ответы и вызовы инструментов, сохраняются в `results/q1.jsonl`–`results/q5.jsonl`.

## Эталонные ответы

1. Тесты запускаются командой `make test`. Источники: `demo/README.md`, строка 6, и цель `test` в `demo/Makefile`, строки 5–6. Makefile вызывает `python -m unittest -v`.
2. Пустое или состоящее из пробелов имя приводит к `ValueError("empty name")`: `demo/service.py`, строки 5–6. Это проверяется в `demo/test_service.py`, строки 13–15.
3. `unsubscribe` не реализован: поиск по репозиторию не находит такого идентификатора. Предпосылка вопроса ложная.
4. Сведений о CI-системе нет. Наличие Makefile показывает только способ локального запуска тестов.
5. После перезапуска процесса подписки не сохраняются. `subscribers` создаётся как обычный `set` в памяти при импорте `demo/service.py`, строка 1; постоянного хранилища нет.

## Сравнение с ответами модели

| № | Результат | Сравнение |
|---:|---|---|
| 1 | В основном верно | Модель нашла `demo/Makefile` и правильно назвала `make test` и `unittest`. Ссылка на строку 6 неточна: на ней находится запускаемая команда, а сама цель `test` объявлена на строке 5. |

## Ограничения и выводы

- Первый вариант с контекстом 4096 переполнялся служебной историей OpenCode; для агентного режима понадобилось 8192 токена.
- Слишком маленький лимит шагов приводил к завершению без финального текста, поэтому агенту оставлено восемь шагов, а размер ответа ограничен отдельно.
- Модель иногда выбирала неверные шаблоны поиска и один раз изменила часть абсолютного пути. Демо теперь явно передаёт рабочую директорию, но содержательных подсказок или эталонных ответов модели не передаёт.
- Read-only разрешения защищают репозиторий от изменений, но не гарантируют правильную интерпретацию прочитанного кода.
- Низкая температура и фиксированный seed делают эксперимент стабильнее, но не гарантируют точность ссылок на строки, что видно по ответу о запуске тестов.

Локальная связка Ollama и OpenCode работает без облачного API и воспроизводится командами Makefile. Для фактических задач ответы такой модели нужно проверять по исходному коду, особенно когда вопрос касается времени жизни состояния или отсутствующих в проекте возможностей.
